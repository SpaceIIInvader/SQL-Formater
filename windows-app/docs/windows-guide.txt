SQL Atelier для Windows x64

ОСНОВНОЙ РЕЖИМ — SQL-КОД
Разделы выбираются в меню слева: «SQL-код», «Папка SQL», «Сравнение SQL»
и «Настройки пресета». Пресет и регистр находятся сверху и общие для всех разделов.
Кнопки «Открыть…» и «Вставить» относятся к исходнику; «Копировать» и
«Сохранить…» — к результату. Разделитель между полями можно перемещать.
«Открыть…» читает UTF-8, UTF-16 с BOM и Windows-1251 (при невалидном UTF-8).
«Сравнить с исходником» открывает сравнение исходного SQL с результатом.

Приложение открывается на вкладке «SQL-код».
1. Вставьте SQL в левое поле через Ctrl+V.
2. Выберите пресет INI и регистр слов в верхней части окна.
3. Нажмите «Форматировать» или Ctrl+Enter.
4. Сравните исходный код слева с результатом справа.
5. Нажмите «Копировать результат» или «Сохранить результат…».
Результат сохраняется в UTF-8 с переносами CRLF. Исходный текст слева
не заменяется. Изменение исходника, пресета или регистра сбрасывает результат.
Галочка «Синхронная прокрутка» связывает перемещение обоих полей вверх-вниз
и влево-вправо.
Снятая галочка позволяет прокручивать каждое поле независимо. По умолчанию
она выключена. Сопоставление пропорциональное: после форматирования строки
могут добавляться, поэтому совпадение участков SQL приблизительное.
Если SQL содержит ошибку, сообщение выводится под полями, старый результат
недоступен для копирования и сохранения. Режим кода не изменяет файлы в папке.

СРАВНЕНИЕ SQL
Откройте третью вкладку «Сравнение SQL». Вставьте первую версию запроса,
процедуры или пакета в левое поле, вторую — в правое. Оба поля редактируются.
«Сравнить» или Ctrl+Enter показывает различия по строкам в таблице снизу.
Красный фон слева означает удалённую строку, зелёный справа — добавленную.
Изменённая строка показывается как удаление старой и добавление новой.
Номера строк относятся к соответствующей версии; вставки не сдвигают
сопоставление следующих совпадающих строк. Кнопки «↑ Различие» и
«↓ Различие» переходят по изменённым строкам с возвратом к началу/концу.
По умолчанию включено «Скрывать совпадающие строки»: возле изменений
остаётся по три строки контекста. Длинные совпадающие участки заменяются
голубой строкой «Совпадает строк: N». Щёлкните по ней или нажмите Enter /
пробел на выбранной строке, чтобы раскрыть этот участок. «Свернуть все
совпадения» снова скрывает раскрытые блоки. Снимите галочку, чтобы увидеть
весь код. Переход по различиям пропускает скрытые блоки; номера исходных
строк сохраняются. Сворачивание не изменяет тексты в полях ввода.
Регистр, отступы и пробелы учитываются; CRLF и LF считаются одинаковыми.
Для сравнения после выравнивания нажмите «Выровнять и сравнить».
Оба текста заменяются отформатированными версиями с текущим пресетом
и регистром. Если выравнивание или сравнение завершилось ошибкой,
исходные тексты сохраняются. Форматирование не доказывает равнозначность SQL.
Текст поля можно выделить через Ctrl+A и скопировать через Ctrl+C.
В таблице Ctrl+C копирует выбранные ячейки; длинные строки можно увидеть
во всплывающей подсказке или расширить колонку за её правую границу.
После редактирования любого поля предыдущая таблица различий очищается.
Можно оставить одно поле пустым, чтобы увидеть все строки как добавления
или удаления. Тексты этой вкладки не сохраняются после закрытия приложения.
Лимиты: до 10 000 строк на сторону; произведение размеров изменённых
участков (с учётом служебной строки) — до 4 млн ячеек алгоритма сравнения.
При превышении лимита сравните отдельный запрос или процедуру.

НАСТРОЙКИ ПРЕСЕТА
Четвёртая вкладка показывает параметры выбранного вверху INI-пресета.
Для поиска используйте поле над таблицей: оно ищет по секции, названию
и описанию параметра. Можно выбрать секцию и включить «Только поддерживаемые».
Изменённые значения сохраняются при фильтрации; применение учитывает все строки.
Для каждого параметра указаны секция, название, значение, описание
и поддержка движком. Меняйте только столбец «Значение».
Значения должны быть целыми числами от 0 до 1000. Для переключателей
используйте 0 (нет) или 1 (да); для регистра — 0 (сохранить), 1 (нижний),
2 (верхний), 3 (с заглавной). Чтобы регистр из пресета действовал,
выберите вверху «Регистр из пресета».
«Применить настройки» обновляет пресет для SQL-кода, обработки папки
и выравнивания при сравнении. Предыдущие результаты и план обработки
папки очищаются: выполните форматирование или анализ заново.
Применённые изменения сохраняются в настройках приложения, в том числе
при редактировании встроенного пресета, и восстанавливаются при запуске.
Для выбранного файла изменённая копия имеет приоритет над INI на диске.
«Сохранить INI как…» применяет правки и записывает пресет в выбранный
файл UTF-8. Комментарии и неподдерживаемые параметры сохраняются.
Исходный INI автоматически не перезаписывается.
«Отменить правки» возвращает значения последнего применённого пресета.
«Встроенный пресет» сразу возвращает встроенные настройки во всех режимах.
Загрузка другого INI обновляет таблицу и заменяет неприменённые правки.
Параметры с отметкой «Не применяется» сохраняются в INI, но не влияют
на форматирование. Предел размера пресета — 60 000 символов.

ОБРАБОТКА ПАПКИ
Для пакетной работы переключитесь на вкладку «Обработка папки».
Выберите папку, выполните анализ, просмотрите результат и сохраните изменения.
Настройки пресета и регистра общие для обеих вкладок.

ЗАПУСК
Запустите SQLAtelier.exe. Установка не нужна.
Нужна Windows с .NET Framework 4.8 (стандартный компонент современных Windows 10/11).
Node.js и движок форматирования встроены в EXE. При первом запуске они
распаковываются в пользовательскую временную папку %TEMP%\SQLAtelier.
Интернет и браузер не используются.

НАСТРОЙКИ
Рядом с EXE находится SQLAtelier.settings.json. Приложение автоматически
сохраняет в него изменения и восстанавливает их при следующем запуске:
  FolderPath — последний путь к папке с SQL;
  PresetFile — путь к выбранному INI (пустая строка означает встроенный);
  PresetText — копия выбранного INI на случай, если файл станет недоступен;
  PresetEdited — при true используется изменённый PresetText, даже если
    исходный INI доступен; для встроенного пресета изменения также сохраняются;
  IncludeSubfolders — обработка вложенных папок (true/false);
  CaseSelection — 0: пресет, 1: сохранить регистр, 2: нижний, 3: верхний;
  WindowWidth / WindowHeight / WindowMaximized — размер и состояние окна;
  LastBackupFolder — последняя папка резервных копий.
Настройки записываются автоматически после изменения, перед анализом
и при закрытии окна. SQL-файлы при запуске автоматически не обрабатываются.
Файл JSON можно редактировать вручную при закрытом приложении.
При очередном сохранении предыдущая версия остаётся в файле .json.bak.
Если JSON повреждён, он переносится в .json.invalid-<дата>-<идентификатор>,
а приложение использует стандартные настройки.

КАК ВЫРОВНЯТЬ ВСЕ ФАЙЛЫ
1. В поле «Папка с SQL» вставьте путь, например:
   C:\Users\d.grebenkin\Documents\GitHub\talian_migrations\sql\objects\packages
   Или нажмите «Выбрать папку».
2. Ваш preset_ibeexpert.ini уже встроен. Другой INI можно выбрать отдельно.
3. При необходимости включите обработку вложенных папок.
4. Нажмите «Проверить и выровнять».
   Приложение прочитает все отдельные файлы .sql, не меняя их на диске.
   Щёлкните по файлу в списке, чтобы сравнить исходник и результат.
5. Нажмите «Сохранить файлов: N».
   Файлы с ошибками и файлы без изменений не перезаписываются.

РЕЗЕРВНАЯ КОПИЯ
Перед заменой каждого файла его точная исходная копия сохраняется в:
  <выбранная папка>\.sql-atelier-backup\<дата-время-идентификатор>\<путь файла>
Структура вложенных папок сохраняется. Кнопка «Открыть резервную копию»
откроет эту папку в Проводнике. Для отмены изменений скопируйте нужные
исходные файлы обратно с заменой.
Папки .git, node_modules и .sql-atelier-backup, а также символические ссылки
при обходе пропускаются. Если исходник изменился после проверки, сохранение
этого файла пропускается: выполните анализ заново.

КОДИРОВКИ И ПРЕСЕТ
General.EmptyLinesNumber задаёт число пустых строк между операторами тела:
запросами и вызовами процедур, перед проверками IF, между проверками,
между проверкой и присваиванием, между присваиванием и запросом.
Во встроенном пресете стоит 1; 0 отключает добавление пустых строк.
Серия DECLARE и серия присваиваний остаются без дополнительных пустых строк.
Перед закрывающим END и финальным SUSPEND лишние пустые строки не вставляются.
Точка с запятой внутри строки или комментария не считается терминатором.
Комментарий на той же строке остаётся с предыдущим оператором; пустые
строки добавляются после него. В конце файла пустые строки не добавляются.
KeepEmptyLines отдельно управляет сохранением уже имеющихся пустых строк.
Если используется ранее сохранённый пресет, на вкладке «Настройки пресета»
задайте General.EmptyLinesNumber=1 и нажмите «Применить настройки».

ДОПОЛНЕННЫЕ ПРАВИЛА ПРЕСЕТА
InputOutput.AlignTypeDefinitions выравнивает типы входных параметров
и RETURNS по самому длинному имени в каждом списке. При 0 выравнивания нет.
DeclareSection.AlignTypeDefinitions выравнивает типы DECLARE VARIABLE
внутри одной секции объявлений. Имена, типы, строки и комментарии не меняются.
DeclareSection.CRLFBeforeSELECT и IndentBeforeSELECT управляют переносом
и отступом SELECT в DECLARE CURSOR FOR (...), а не обычными запросами тела.
Insert.CRLFAfterMatching распознаётся в написании приложенного INI;
имена параметров сопоставляются без учёта регистра букв.
Insert.IndentBeforeMATCHINGColumns задаёт отступ продолжения списка MATCHING.
IndentBeforeRETURNINGColumns в Insert, Update и Delete задаёт отступ
RETURNING при переносе после ключевого слова или между элементами.
Для переноса каждого элемента включите OneReturningColumnInLine.
IfThenElse.CRLFBeforeAND/CRLFAfterAND/CRLFBeforeOR/CRLFAfterOR действуют
на внешнем уровне условия IF, в том числе внутри его внешних скобок.
AND в BETWEEN не разрывается. Case.IndentBeforeTHENExpression задаёт
отступ выражения после переноса THEN/ELSE при CRLFAfterTHEN=1.
Эти настройки работают в браузере и приложении Windows.
Полного совпадения с IBExpert пока нет: например, EXISTS может разбиваться
на большее число строк. Если CRLFAfterAND=1 в IfThenElse, условия IF
переносятся после AND, даже если исходник был записан в одну строку.

Автоматически определяются UTF-8, Windows-1251, UTF-16 LE/BE с BOM.
Кодировка, наличие BOM и стиль переносов строк сохраняются.
Другие кодировки могут определяться неверно: проверьте предпросмотр.
Пресет поддерживается частично: используется тот же собственный движок,
что в браузерном приложении. Точное совпадение с IBExpert не гарантируется.
После анализа нажмите строку о поддержке INI, чтобы увидеть список
неприменяемых параметров. Регистр можно переопределить в окне приложения.
SQL перед сохранением проверяется на сохранность токенов; он не выполняется
и не компилируется в базе данных.
Лимиты: 5000 SQL-файлов за проход, 64 МБ исходных файлов в сумме,
8 МБ на файл и 2 млн символов для форматирования одного файла.

ПРОВЕРКА СБОРКИ
Проверены встроенный движок EXE, инициализация окна, анализ временной папки,
пакетное сохранение, точность резервных копий, исключение резервной папки,
кодировки и повторное форматирование без новых изменений.
Ваши рабочие SQL-файлы при тестировании приложения не изменялись.

Node.js содержит компоненты с открытым исходным кодом.
Полный текст лицензий находится в licenses\node-license.txt; копия также встроена в EXE.
